# QA Report Connect 0.4.1

QA Report Connect — новое название приложения подключения к Jira. Окно и трей
получают новое название, иконка — надпись CONNECT. Идентификатор приложения,
протокол `qareport-agent`, каталоги настроек и канал обновлений сохраняются.
Обновление кода меняет окно и трей; имя программы в ОС и иконку установщика
обновляет полная сборка. Полные установщики 0.4.1 доступны в GitHub Release
для macOS Apple Silicon и Windows x64.

## Необязательный заголовок Jira

В Connect откройте «Изменить» у нужной Jira и задайте «Имя заголовка» и «Значение»,
выданные ИБ. «Сохранить и проверить» сохраняет их в локальном профиле этой Jira
вместе с доступом (0600 на macOS, права пользователя на Windows).
Пустое значение сохраняет прежний ключ для того же адреса и имени заголовка.
Очистите оба поля, чтобы удалить настройку. Действующий токен или cURL
не нужно вводить повторно. Результат проверки виден сразу под подключениями.

В серверном режиме откройте «Настройки → Jira → Через сервер QA Report».
Пара сохраняется в localStorage `qa-report-jira-headers-v1` без шифрования,
отдельно для полного адреса Jira, включая context path. Jira-токен по-прежнему
остаётся только в памяти вкладки. Заголовок передаётся серверу только при
обращении к выбранной Jira; постоянное серверное хранилище для него не создаётся.
В режиме Connect настройка задаётся в Connect: браузер не передаёт свой ключ
в задания. Ключ не включается в отчёты, экспорт, feedback или снимки Connect.

Заголовок используется при проверке, чтении и публикации комментариев,
получении метаданных, загрузке и скачивании вложений. Сетевая проверка использует
его только для точно совпадающего сохранённого подключения. Служебные заголовки
авторизации, Cookie, Host, User-Agent, Content-Type и X-Atlassian-Token нельзя
переопределять. Переносы строк и управляющие символы запрещены. Jira-запросы
не следуют перенаправлениям; ключ не отправляется за пределы origin и context path.

## Размещение установщиков

Для скачивания без входа в GitHub репозиторий и Release должны быть публичными.
Приватный репозиторий возвращает 404 пользователю без доступа, даже если владелец
успешно скачивает файл. В ссылки нельзя добавлять GitHub-токены.

Имена, размеры и SHA-256 установщиков перечислены в `scripts/agent-release.json`.
После публикации выполните из корня `node scripts/check-agent-downloads.js`:
скрипт без GitHub-авторизации скачивает обе сборки потоково, проверяет размер
и SHA-256 и завершает работу с ошибкой при недоступном или повреждённом файле.
Только после этой проверки обновляйте каталог и развёртывайте сайт.
Установщики 0.4.1 уже содержат текущий код и иконку CONNECT. Существующие
установки 0.4.0 также поддерживают подписанное обновление кода до 0.4.1.

Архивы CLI `/downloads/qa-report-agent-macos.zip` и
`/downloads/qa-report-agent-windows.zip` раздаются самим сайтом. Они содержат
актуальный код, модуль заголовков и скрипт запуска для соответствующей ОС.

Подписанные ASAR раздаются как раньше из `agent-update-feed/` через
`/agent-updates/`. Сначала размещается ASAR, затем `latest.json`.
Не удаляйте прежний ASAR: он может быть указан в ранее полученном каталоге.
Закрытый ключ подписи на сайт не загружается.

## Проверки

`npm run check`, `npm test`; браузерные сценарии `scripts/test-agent-web.cjs`
и `scripts/test-agent-desktop.cjs` используют Playwright (`QA_REPORT_PLAYWRIGHT`),
изолированные профили и тестовые ответы Jira. Последний сценарий запускает
настоящий Electron и проверяет подписанное обновление после завершения задания.
