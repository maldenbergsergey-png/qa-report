# Частичная публикация чек-листа в Jira

Этот документ фиксирует поведение личной версии QA Report и служит заметкой для
последующего переноса функции в корпоративную версию.

## Пользовательский сценарий

- Если в чек-листе один раздел, используется прежнее подтверждение отправки.
- Если разделов больше одного, действие «Отправить в Jira» сразу открывает окно
  выбора разделов.
- При каждом открытии выбраны все разделы.
- Общий флажок «Все разделы» включает или выключает весь список.
- Частичный выбор переводит общий флажок в промежуточное состояние.
- Нельзя продолжить публикацию, пока не выбран хотя бы один раздел.
- После подтверждения окно выбора закрывается и открывается существующее окно
  прогресса публикации.

## Контракт публикации

Выбор передаётся внутри текущего запуска публикации как набор стабильных
`sectionId`. Он не записывается в черновик и не меняет сам чек-лист.

Один и тот же набор `sectionId` обязательно применяется к двум операциям:

1. генерации Jira Wiki Markup или Atlassian Document Format;
2. сбору локальных изображений и файлов для загрузки.

За счёт этого вложения из невыбранных разделов не отправляются отдельно от
отфильтрованного комментария. Общая вводная часть отчёта и её вложения остаются
общими и публикуются при любом выборе разделов.

Пустые разделы обрабатываются так же, как в полной публикации: если в разделе нет
строк с содержимым, таблица не добавляется в комментарий.

## Точки реализации

- `sectionsForPublication` — единая фильтрация разделов по `sectionId`;
- `generateMarkup` и `generateAdfDocument` — формирование выбранной части отчёта;
- `collectLocalImages` и `collectLocalFiles` — отбор вложений из тех же разделов;
- `uploadPendingImages` — передача области публикации в сборщики вложений;
- `askPublishScope` и `resolvePublishScope` — временный выбор пользователя;
- `publishToJira` — развилка между старым подтверждением и новым окном.

Серверный API не менялся: фильтрация выполняется до запросов
`/api/jira/attachments` и `/api/jira/comment`.

## Перенос в корпоративную версию

При переносе нужно сохранить следующие инварианты:

- идентификаторы разделов должны быть стабильными;
- выбранная область не должна сохраняться в документе;
- один фильтр должен использоваться и для отчёта, и для вложений;
- для одного раздела должен сохраниться прежний сценарий подтверждения;
- существующее окно прогресса и обработка отмены публикации должны остаться
  общими для полной и частичной отправки;
- необходимо проверить оба формата Jira: Wiki Markup и ADF.

## Будущий фильтр по статусам

Фильтр статусов намеренно не включён в текущее окно: базовое требование
предписывает показывать в нём только разделы и сохранять минималистичный
интерфейс.

Для расширения область публикации следует заменить с набора `sectionId` на
объект вида:

```js
{
  sectionIds: Set<string>,
  statuses: Set<string> | null,
}
```

Фильтрация статусов должна применяться внутри уже выбранных разделов до
генерации таблиц. Сбор вложений при этом должен использовать итоговый набор
строк, а не только набор разделов, иначе файлы из исключённых по статусу пунктов
попадут в Jira.
