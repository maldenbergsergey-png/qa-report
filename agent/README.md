# QA Report Local Agent

Локальный агент обращается к Jira с компьютера пользователя через корпоративные
DNS и VPN-маршруты. Графическая версия `0.3.6` с ядром `0.2.8` поддерживает
проверку подключения, публикацию комментариев, загрузку и импорт вложений.

## Запуск

1. Установите Node.js 18 или новее.
2. Подключите корпоративный VPN.
3. Запустите `start.command` на macOS, `start.cmd` на Windows или `start.sh` на Linux.
4. Введите адрес QA Report и 8-значный код из окна «Локальный агент».
5. Выберите способ Jira-авторизации. Для SSO/2FA используйте Copy as cURL из
   авторизованной вкладки Jira; поддерживаются форматы bash и Windows cmd,
   credential извлекается и сохраняется только локально.
6. Оставьте окно агента открытым и отправляйте чек-лист обычной кнопкой QA Report.

На Windows `start.cmd` автоматически использует сертификаты из системного
хранилища. Это нужно в корпоративных сетях, где VPN, proxy или антивирус
проверяет HTTPS с помощью установленного организацией сертификата.

Чтобы обновить Jira credential после истечения cookie:

```bash
node qa-report-agent.js --configure-jira
```

Чтобы удалить локальную привязку, выполните:

```bash
node qa-report-agent.js --reset
```

Ключ сопряжения и Jira credential хранятся только на устройстве в конфигурационном
файле с ограниченными файловыми правами. Агент не является универсальным
HTTP-прокси и выполняет только явно разрешённые Jira-команды.

## Графический агент (дополнение к CLI)

Electron + electron-builder, отдельный пакет `agent/package.json`. Node.js включён
в приложение; системная установка Node.js не проверяется и не изменяется.

1. В настройках подключения QA Report скачайте установщик для своей платформы.
2. Установите приложение. На macOS перенесите его из DMG в Applications и откройте.
3. Вернитесь в QA Report → «Подключить графический агент» → «Открыть QA Report Agent».
4. Подтвердите адрес QA Report в агенте. Код и имя компьютера передаются автоматически.
5. При отсутствии сохранённых настроек введите Jira и данные входа либо вставьте
   Copy as cURL. Сохранение выполняется только после успешной проверки `/myself`.
6. Закройте окно: агент остаётся в трее. Автозапуск включается переключателем
   на Windows/macOS; на Linux используется настройка автозапуска рабочего стола.

CLI и GUI используют один локальный файл настроек. Не запускайте их одновременно:
они представляются серверу одним устройством. Повторная привязка сохраняет Jira,
но заменяет привязку QA Report. Публичному серверу передаётся только адрес Jira,
чтобы заполнить поле в браузере, без токена/cookie. Истечение кода требует повторного
нажатия кнопки в браузере. Браузер не определяет наличие выключенного приложения.

### Сборка и доставка

В каталоге `agent`: `npm ci`, затем `npm run dist` на целевой ОС.
Конфигурация собирает macOS Intel/Apple Silicon (DMG), Windows x64/ARM64
(единый NSIS EXE), Debian/Ubuntu x64/ARM64 (DEB). Есть ручной GitHub Actions
workflow `.github/workflows/agent-desktop.yml`, не публикующий релиз автоматически.

Скопируйте готовые `qr-report-agent-*.dmg`, `qr-report-agent-*.exe`,
`qr-report-agent-*.deb` из `agent/dist` в `downloads` **до сборки Docker-образа**.
API `/api/agent/downloads` показывает только реально присутствующие установщики
как доступные для скачивания. На сайте отсутствующие сборки отмечены явно.
Бинарные сборки исключены из Git; переносите их как артефакты выпуска.

Для публичного выпуска нужны подпись Windows и Developer ID + notarization macOS.
Без сертификатов получаются тестовые неподписанные сборки с возможными блокировками
ОС. Workflow принимает `AGENT_CSC_LINK`, `AGENT_CSC_KEY_PASSWORD`,
`AGENT_WIN_CSC_LINK`, `AGENT_WIN_CSC_KEY_PASSWORD`, `AGENT_APPLE_ID`,
`AGENT_APPLE_APP_SPECIFIC_PASSWORD`, `AGENT_APPLE_TEAM_ID` через GitHub Secrets.

GUI использует системные доверенные CA и ранее сохранённый `jira-extra-ca.pem`.
При ошибке TLS нужно установить доверенный корпоративный сертификат средствами
ОС/ИТ-службы либо исправить цепочку на Jira. Проверка TLS не отключается.
Проверка Jira в GUI подтверждает авторизацию, кнопка в браузере сохраняет прежнюю
семантику проверки сетевой доступности. Автообновление бинарного агента пока не включено:
обновление выполняется новым установщиком с сохранением локальной конфигурации.

### Версия 0.3.1

Агент следует теме браузерного приложения (светлая/тёмная; graphite отображается
тёмной). Тема передаётся при сопряжении и обновляется при работающем агенте.
Настроенный доступ скрыт за кнопкой «Изменить доступ». Публикация берёт адрес Jira
из ссылки задачи, игнорируя устаревший адрес в браузере; агент по-прежнему
отклоняет задачи из другой Jira. В статусе устройства передаётся версия GUI.

### Хранение установщиков

Установщики доступны в Google Диске:
https://drive.google.com/drive/folders/1WLFearsEBhE_89A6r87KfxtEXQznoKUv
Кнопка «Скачать» открывает выбранный файл в новой вкладке. Для больших файлов
Google Диск может показать дополнительное подтверждение скачивания.
Ссылки и SHA-256 хранятся в `scripts/agent-release.json`.
Docker больше не скачивает все установщики: для работы публичных ссылок
файлы на сервере приложения не нужны.

Резервная копия остаётся в GitHub Releases (`agent-v0.3.3`). Для локального
зеркала доступна команда `npm run agent:download`, проверяющая SHA-256.
macOS-образы переупакованы с корректной ad-hoc подписью. Она подтверждает
целостность, но не заменяет Developer ID и нотариализацию Apple. Для релиза
без предупреждений Gatekeeper нужна подпись сертификатом разработчика Apple
(переопределить `mac.identity` при сборке) и нотариализация.
Название приложения: **QA Report Agent**. Технические имена файлов и протокол
запуска сохранены для совместимости существующих ссылок.

### Проверка установщика Windows

В electron-builder 26.15.3 новый архиватор создаёт BCJ2/ARM64-потоки,
которые встроенный распаковщик NSIS может пропускать без ошибки.
`build/before-pack.js` принудительно выбирает совместимый BCJ для Windows.
Установщик проверяет наличие основного EXE до записи информации об установке.
CI выполняет настоящую тихую установку на Windows и проверяет EXE и DLL.

### Сертификаты Jira в графическом агенте

Запросы Jira выполняются через отдельную непостоянную сессию Chromium:
системное доверие к корпоративным CA, построение цепочки и системные прокси.
Это помогает при неполной цепочке, если промежуточные сертификаты доступны,
а корневой сертификат уже доверен в ОС. Неизвестные CA не импортируются
автоматически; ошибки срока действия и имени узла также не обходятся.
Токены задаются явно, сессионные cookie не подмешиваются, редиректы не
выполняются автоматически. CLI сохраняет прежний сетевой транспорт.

## Импорт вложений

Ядро CLI 0.2.8 поддерживает загрузку оригиналов изображений и файлов при импорте
комментария Jira. Команда проверяет принадлежность вложения задаче, использует
локальные credentials только для разрешённой Jira и не следует перенаправлениям.
Максимальный размер файла — 50 МБ. В редакторе включите «Импортировать с вложениями».
Для графического агента установите версию 0.3.6 или новее. Перед установкой
завершите старый агент через меню в трее; настройки подключения сохранятся.
Автоматическое обновление не включено: одной перезагрузки страницы недостаточно.
CI проверяет версию и точное совпадение ядра внутри собранного приложения
с исходниками, а также импорт оригинальных файлов через транспорт Chromium.

Версия 0.3.6 (ядро 0.2.8) проверяет список вложений задачи перед повторной публикацией. Неизменённые файлы используются повторно; при загрузке новых сохраняются исходные имена с суффиксом при конфликте. Команда `jira.attachment-manifest` ограничена настроенной Jira и не возвращает локальные credentials.
