# QA Report Agent

Графический агент **0.4.0**, ядро CLI **0.3.0**. Поддерживаются только
**macOS на Apple Silicon (M1 и новее)** и **Windows x64**. Linux, Intel Mac и
нативная Windows ARM64 больше не выпускаются.

Агент обращается к Jira из сети пользователя, через его VPN, системный proxy и
доверенные корпоративные сертификаты. Импортирует комментарии и оригиналы
вложений, загружает файлы, публикует и проверяет комментарии. Файлы отчёта
остаются в браузере; Jira credentials — на компьютере.

## Установка и подключение

1. В QA Report откройте «Агент» и скачайте установщик своей платформы с сайта приложения.
2. На Mac перенесите приложение из DMG в Applications. На Windows запустите EXE.
3. Для перехода с 0.3.x сначала завершите старый процесс через меню в трее.
   Однократная установка 0.4.0 добавит механизм дальнейших обновлений.
4. В QA Report нажмите «Подключить», откройте агент и подтвердите адрес сайта.
5. Добавьте Jira: PAT, логин/API token или Copy as cURL из авторизованной вкладки Jira.
   Настройки сохраняются только после успешной проверки доступа.
6. Закрытие окна оставляет агент в трее. Автозапуск настраивается в его окне.

Приложение содержит Electron, Chromium и Node.js; системный Node.js для GUI не
нужен. Исключение только Node.js не устраняет основную массу Chromium.
Windows-установщик содержит одну архитектуру. Обычные обновления передают только
логику и интерфейс агента, поэтому существенно меньше полного установщика.

## Несколько Jira

«Добавить Jira» сохраняет новое подключение; можно задать короткое название.
У каждого подключения есть проверка, изменение данных входа и удаление.
Допускается до 10 подключений. Для одного адреса хранится один набор credentials.

Старый `jira` автоматически переносится в `jiras`, ключ привязки и данные входа
сохраняются. Запись конфигурации атомарная с ограниченными файловыми правами.
CLI и GUI используют один файл: одновременно запускать их не следует.

Импорт/публикация выбирают Jira по адресу задачи или комментария, включая context
path (`https://host/jira-one` и `https://host/jira-two` различаются). Устаревшая
настройка браузера не переопределяет ссылку. Неизвестная Jira отклоняется до
отправки credentials. Серверу QA Report сообщаются только адреса подключений,
без токенов, cookies, логинов и пользовательских названий. В окне подключения
браузера можно выбрать сохранённый адрес; обновление статуса его не сбрасывает.

## Обновления без повторной установки

После запуска агент проверяет выпуск через 10 секунд, затем каждые 6 часов.
«Проверить сейчас» запускает проверку немедленно. По умолчанию новый пакет
скачивается автоматически. Он устанавливается, когда окно закрыто и агент
не выполняет задания хотя бы 2 минуты. Можно отключить автоматическую установку
и пользоваться кнопками загрузки и перезапуска.

При ручной установке прекращается получение новых заданий, текущее Jira-задание
завершается вместе с отправкой результата в QA Report, затем агент перезапускается.
Скачанный пакет можно установить без сети. Настройки подключения не заменяются.

Пакет содержит только JavaScript, HTML, CSS и ресурсы агента, без Electron и Node.
Bootstrap внутри приложения проверяет Ed25519-подпись каталога, совместимость,
размер и SHA-256 пакета. Перед каждым запуском внешнего кода проверка повторяется.
При повреждении или неудачном первом запуске восстанавливается предыдущий пакет
либо встроенная версия; неудачный выпуск повторно автоматически не применяется.
Исправление выпускается с новым номером. Понижение версии через кнопку проверки
не поддерживается. Подписанное поле `minimumVersion` выделяет необходимое обновление,
но не прерывает работу пользователя и не отменяет его выбор автоматической установки.

Канал обновлений зафиксирован в `bootstrap/policy.json`, по умолчанию
`https://qa-report.mlbrg.ru/agent-updates/`. Привязка к другому QA Report не меняет
источник исполняемого кода. Загрузки не содержат Jira credentials или ключа привязки,
не следуют redirect и используют HTTPS с проверкой доверия ОС.

### Ограничение обновления среды

Bootstrap, его публичный ключ и Electron меняются полным установщиком. Для этого
нужно изменить `runtimeVersion` в политике и собрать новый установщик. Обычные
выпуски оставляют `runtimeVersion` прежним; номер `agent/package.json` повышается.
Новая среда показывается как «Скачать приложение». Полная замена macOS-приложения
через Squirrel требует постоянной подписи разработчика. Текущая схема обновляет
подписанные пакеты приложения в профиле пользователя и не меняет установленный
подписанный bundle. Она не требует аккаунта Apple Developer. Ad-hoc подпись DMG
не заменяет Developer ID/notarization и не снимает предупреждения Gatekeeper.

## Сборка

В `agent`: `npm ci`, затем:

```sh
npm run dist -- --mac --arm64
npm run dist -- --win --x64
```

Сборка другой платформы или архитектуры отклоняется. Ручной workflow
`.github/workflows/agent-desktop.yml` собирает только эти два установщика.
BCJ-фильтр Windows и проверка EXE/DLL после NSIS-установки сохранены.

### Выпуск маленького обновления

Один закрытый Ed25519-ключ используется для всей линии установленных агентов.
Его публичная часть находится в `bootstrap/release-key.pem`. **Закрытый ключ не
должен попадать в Git, Docker-образ, публичный каталог или архив для сервера.**
Храните отдельную резервную копию: потеря ключа потребует нового установщика.
Скрипт проверяет совпадение ключа со встроенным публичным ключом до выпуска.

1. Повысить версию в `agent/package.json` и `agent/package-lock.json`.
2. Проверить код и собрать пакет из корня публичного проекта:

```sh
AGENT_SIGNING_KEY_FILE=/secure/location/release-private.pem \
AGENT_RELEASE_NOTES='["Короткое описание изменений для пользователя."]' \
node scripts/build-agent-update.cjs /path/to/release/site
```

3. При необходимости задать `AGENT_MINIMUM_VERSION=0.4.1` (не выше выпускаемой версии).
4. Загрузить `qr-report-agent-code-<version>.asar` на сервер, **после него** заменить
   `latest.json` атомарным переименованием. Старые пакеты пока оставить: клиент мог
   получить предыдущий каталог непосредственно перед публикацией.

Для CI есть ручной workflow `.github/workflows/agent-update.yml`; секрет
`AGENT_RELEASE_SIGNING_KEY` должен содержать тот же закрытый ключ. Workflow
возвращает только публичные ASAR и каталог, не публикуя их автоматически.

Полный установщик для каждого исправления логики собирать не нужно. При первой
установке старой версии агент получает актуальный совместимый пакет по тому же каналу.

## Хостинг в QA Report

Установщики и обновления хранятся в одном отдельном каталоге `agent-releases` рядом
с `compose.yaml`; Compose подключает его read-only к `/app/agent-releases`.
Для другого развёртывания задайте `AGENT_RELEASE_DIR`. Бинарники не входят в Git
или Docker-образ. Файлы каталога:

- `qr-report-agent-mac-arm64.dmg` и `qr-report-agent-windows-setup.exe`;
- `installers.json` с версией установщиков и SHA-256;
- `qr-report-agent-code-<version>.asar` и `latest.json` с подписью.

Сайт отдаёт установщики через `/downloads/<filename>`, каталог обновлений через
`/agent-updates/latest.json`, пакеты через `/agent-updates/<filename>`.
`/api/agent/downloads` предлагает только две поддерживаемые платформы и помечает
отсутствующие файлы недоступными. Большие файлы передаются потоком, поддерживаются
HEAD и Range. Произвольные пути, символьные ссылки и приватные ключи не раздаются.
Google Drive для новой доставки не используется. Для проверки скачиваемой копии
доступен `npm run agent:download -- /path/to/mirror`: SHA-256 берётся из
`scripts/agent-release.json` соответствующего полного выпуска.

## Регрессионные проверки

Из корня: `npm run check`, `npm test`. Из `agent`:

```sh
npx electron build/verify-network.cjs
npx electron build/verify-xsrf.cjs
```

Они проверяют Chromium TLS, отсутствие посторонних cookies, запрет redirect,
PAT/basic/cookie, multipart, импорт и подтверждённую публикацию комментария.
`User-Agent: QA-Report-Agent/<version>` и `X-Atlassian-Token: no-check` сохранены:
регрессия браузерной XSRF-проверки не должна возвращаться.

`QA_REPORT_PLAYWRIGHT=/path/to/playwright node scripts/test-agent-desktop.cjs`
запускает настоящий Electron на временных данных: загрузка подписанного ASAR,
миграция старого доступа, две Jira, кнопки обновления, светлая/тёмная темы и
ожидание результата активного задания перед перезапуском. Рабочая Jira,
реальные настройки, автозапуск и регистрация протокола не изменяются.

## CLI

Для ручного запуска доступно то же ядро через `start.command` (Mac arm64) и
`start.cmd` (Windows x64). Нужен Node.js 22 или новее. `--configure-jira` добавляет адрес
или обновляет существующий. `--reset` удаляет локальную привязку и credentials.
Обновление маленькими пакетами относится к графическому приложению; CLI
обновляется заменой файлов. Для обычной работы используйте GUI.
